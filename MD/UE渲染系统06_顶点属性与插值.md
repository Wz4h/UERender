# UE 渲染系统 06：顶点属性与插值

## 一、本节目标

前面我们已经知道：

- 3D 模型通常由大量三角形组成
- 三角形投影到屏幕后，会经过光栅化
- 光栅化会根据三角形覆盖的 Sample，产生对应的 Fragment 候选

那么新的问题来了：

> **Fragment 里的 UV、Normal、Vertex Color 等数据，到底是从哪里来的？**

毕竟模型最明确保存数据的位置，首先是：

```text
Vertex
```

也就是顶点。

所以这一节要解决两个核心问题：

1. 顶点上到底保存了哪些常见属性，这些属性分别有什么用
2. Fragment 为什么能得到三角形内部自己的 UV、Normal、Color 等数据

这就会引出：

# Interpolation —— 插值

---

# 二、顶点不只是一个位置

刚开始学习模型时，我们通常把 Vertex 理解成：

> 3D 空间中的一个点。

例如：

```text
Position = (X, Y, Z)
```

但真实渲染中的 Vertex 往往不只是一个位置。

它更像是一包数据：

```text
Vertex
{
    Position
    UV
    Normal
    Tangent
    VertexColor
    ...
}
```

这些属性会一路参与后面的渲染计算。

---

# 三、Position：顶点位置

Position 最基础。

它表示：

> **这个顶点在空间中的位置。**

例如：

```text
A = (0, 0, 0)
B = (100, 0, 0)
C = (0, 100, 0)
```

这三个点可以形成一个三角形。

如果把 B 改成：

```text
B = (200, 0, 0)
```

三角形就会被拉长。

所以 Position 最直接决定的是：

> **模型的几何形状。**

## Position 在 UE 里有什么用

Position 不只是静态模型位置。

UE 里很多视觉效果本质上都和顶点位置有关，例如：

- World Position Offset
- 草随风摆动
- 水面波浪
- 顶点动画
- 程序化变形
- 植被摆动

比如一个平面原本是：

```text
────────────
```

如果 Shader 根据时间改变顶点高度：

```text
~ ~ ~ ~ ~ ~
```

就可以形成水波效果。

所以可以先记住：

> **Position 决定模型几何在哪里。**

---

# 四、UV：模型表面怎么对应二维贴图

UV 解决的问题是：

> **模型表面上的某个位置，应该去二维图片的哪里取数据？**

为什么需要它？

因为模型是 3D 的：

```text
X
Y
Z
```

但 Texture 通常是二维的：

```text
U
V
```

所以我们需要建立：

```text
3D 模型表面
↔
二维 Texture
```

之间的对应关系。

这个关系就是 UV。

## 一个最简单的 UV 例子

假设有一张二维图片：

```text
(0,0) ---------------- (1,0)
  |                      |
  |       Texture        |
  |                      |
(0,1) ---------------- (1,1)
```

一个三角形三个顶点可以分别保存：

```text
Vertex A
UV = (0,0)

Vertex B
UV = (1,0)

Vertex C
UV = (0,1)
```

这就等于告诉 GPU：

> A 对应图片左上角，B 对应右上角，C 对应左下角。

UV 可以用来采样：

- Base Color
- Normal Map
- Roughness
- Metallic
- AO
- Emissive
- Mask

例如 Pixel Shader 得到：

```text
UV = (0.35, 0.42)
```

就可以去 Texture 的这个位置取值。

所以可以记住：

> **UV 是模型表面访问二维纹理的坐标。**

---

# 五、Normal：表面朝哪个方向

Normal 可以理解成：

> **这个位置的表面朝向。**

例如地面：

```text
      Normal
        ↑
────────────
```

墙面：

```text
墙
│ → Normal
│
│
```

Normal 最大的用途之一就是：

# 光照

因为计算一个表面亮不亮，需要知道：

> 光从哪里来，以及表面朝哪里。

## 一个简单的光照例子

太阳从上方照下来。

如果地面的 Normal 朝上：

```text
Light
↓
↑
Normal
```

那么表面比较正对光源，通常会更亮。

如果墙面的 Normal 朝侧面：

```text
Light
↓
→ Normal
```

它和光照方向差异更大，亮度也会发生变化。

所以：

> **Normal 是光照计算最核心的数据之一。**

---

# 六、为什么低面数 Sphere 也能看起来比较圆

一个 Sphere 的真实几何其实是很多三角形：

```text
△ △ △ △ △
 △ △ △ △
△ △ △ △ △
```

如果每个三角形都完全使用自己的平面方向，光照会出现非常明显的：

```text
一块亮
一块暗
一块亮
一块暗
```

模型看起来就会很“硬”。

但如果顶点上保存平滑的 Normal，然后三角形内部继续插值 Normal，就可以让光照方向连续变化。

于是即使几何还是一个个平三角形，视觉上也可以表现成：

> **一个比较光滑的曲面。**

这就是平滑着色的重要基础之一。

---

# 七、Tangent：沿着表面的方向

Tangent 比 Normal 稍微难理解一点。

Normal 是：

> 离开表面的方向。

Tangent 是：

> **贴着表面延伸的一个方向。**

例如：

```text
        Normal
          ↑
          |
──────────┼────→ Tangent
```

## Tangent 为什么有用

最典型的用途就是：

# Normal Map

Normal Map 里面保存的是表面细小的方向变化。

但这张贴图本身是二维的。

它需要知道：

> 图片里的这个方向，放到当前模型表面以后，到底对应世界里的哪个方向？

这就需要构造一个局部坐标空间：

```text
Tangent
Bitangent
Normal
```

也就是：

# Tangent Space

所以可以先简单理解：

> **Tangent 帮助 Shader 理解贴图中的方向应该如何贴到模型表面。**

---

# 八、Vertex Color：顶点颜色

Vertex Color 表面上看，就是：

> 顶点保存的颜色。

通常有：

```text
R
G
B
A
```

四个通道。

例如三个顶点：

```text
Vertex A = Red
Vertex B = Green
Vertex C = Blue
```

那么三角形内部就可以出现连续渐变。

## Vertex Color 不只是“颜色”

在 UE 中，Vertex Color 很多时候并不是真的拿来显示颜色。

它更常被当成：

> **4 个可以自由使用的数据通道。**

例如：

```text
R = 泥土权重
G = 苔藓权重
B = 湿润程度
A = 其他遮罩
```

### 一个常见例子：材质混合

假设一块石头想混合：

```text
石头
+
苔藓
```

美术可以给顶点刷 Vertex Color。

比如：

```text
R = 0
→ 不长苔藓

R = 1
→ 苔藓很多
```

Shader 就可以根据 Vertex Color 来混合材质。

### 另一个例子：植被摆动

还可以规定：

```text
Vertex Color R = 0
→ 不动

Vertex Color R = 1
→ 可以被风吹动
```

这样：

```text
树干
基本不动

树叶
明显摆动
```

所以 Vertex Color 本质上也可以是：

> **Shader 的控制数据。**

---

# 九、为什么这些数据一开始存在顶点上

这是理解插值之前最重要的问题。

为什么不直接给每个 Fragment 存：

```text
UV
Normal
Color
```

因为 Fragment 不是模型固定的数据。

Fragment 是运行时根据：

- 当前摄像机
- 当前分辨率
- 当前三角形屏幕覆盖面积
- 遮挡情况
- Sample 数量

动态产生的。

也就是说：

> **Fragment 每一帧都可能不同。**

顶点则属于模型资产本身，是稳定数据。

模型可以提前保存：

```text
10 万个 Vertex
```

但一帧产生多少 Fragment 会随着视角和覆盖面积不断变化。

所以不可能在模型资产里提前保存：

> 每一个未来可能产生的 Fragment 的 UV、Normal、Color。

---

# 十、解决办法：只保存关键点的数据

于是 GPU 采用了一个非常自然的思路：

```text
只在 Vertex 上保存属性
↓
Triangle 由 3 个 Vertex 组成
↓
真正产生 Fragment 时
↓
根据 Fragment 在 Triangle 中的位置
↓
临时算出对应属性
```

这个“从已知顶点数据计算中间位置数据”的过程，就是：

# Interpolation —— 插值

---

# 十一、什么是插值

插值可以先用一句话理解：

> **已知几个位置上的数据，计算它们中间位置应该对应什么数据。**

最简单的情况就是：

```text
A ---------------- B
```

假设：

```text
A = 0
B = 100
```

中间位置：

```text
A -------- P -------- B
```

如果 P 正好在中间，那么 P 可以得到：

```text
50
```

这就是最简单的插值。

---

# 十二、插值不是“随便平均”

假设：

```text
A = 0
B = 100
```

如果 P 非常靠近 A：

```text
A -- P ---------------- B
```

那么 P 不应该还是 50，而应该更接近 0。

例如：

```text
10
```

所以插值的核心是：

> **根据当前位置和已知点之间的关系，计算权重。**

离 A 越近，A 的影响越大。

离 B 越近，B 的影响越大。

---

# 十三、线性插值 Lerp

两个值之间最常见的插值方式之一就是：

# Linear Interpolation

通常简称：

# Lerp

它的核心思想很简单：

```text
A 的一部分
+
B 的一部分
=
中间结果
```

例如：

```text
A = 0
B = 100
```

如果：

```text
t = 0
```

结果就是 0。

如果：

```text
t = 1
```

结果就是 100。

如果：

```text
t = 0.5
```

结果就是 50。

可以理解为：

```text
A -------- P -------- B
0         50        100
```

---

# 十四、UE 里其实经常使用 Lerp

如果使用过 UE Material，应该见过：

```text
Lerp
```

节点。

它有：

```text
A
B
Alpha
```

例如：

```text
A = Red
B = Blue
Alpha = 0.5
```

结果就是两者中间的颜色。

Lerp 的本质就是：

> **根据权重，在两个数据之间取中间结果。**

所以插值并不是只存在于底层 GPU，在 UE 材质里也非常常见。

---

# 十五、三角形不是两个顶点，而是三个顶点

线性插值很好理解。

但 Triangle 有：

```text
A
B
C
```

三个顶点。

三角形内部某个 Fragment：

```text
        A
       / \
      / P \
     /     \
    B-------C
```

它需要同时考虑：

```text
A
B
C
```

三个顶点的数据。

---

# 十六、三角形内部插值

可以把 P 的数据理解成：

```text
A 的一部分
+
B 的一部分
+
C 的一部分
```

例如：

```text
A 权重 = 0.5
B 权重 = 0.3
C 权重 = 0.2
```

三个权重相加：

```text
0.5 + 0.3 + 0.2 = 1
```

那么：

```text
P
=
A × 0.5
+
B × 0.3
+
C × 0.2
```

这就是理解三角形内部插值最重要的思想。

---

# 十七、为什么三角形特别适合插值

一个三角形内部任意一个位置，都可以根据 A、B、C 三个顶点确定出一组权重。

所以可以稳定地计算：

```text
P 的数据
```

这也是三角形在实时渲染中非常方便的原因之一。

它不只是几何结构简单稳定，还非常适合：

> **在内部连续传递数据。**

---

# 十八、UV 是怎么插值出来的

例如：

```text
Vertex A
UV = (0,0)

Vertex B
UV = (1,0)

Vertex C
UV = (0,1)
```

Fragment P 位于三角形内部。

假设 P 对三个顶点的权重分别是：

```text
A = 0.3
B = 0.4
C = 0.3
```

那么 P 的 UV 可以理解成：

```text
UV(P)
=
UV(A) × 0.3
+
UV(B) × 0.4
+
UV(C) × 0.3
```

最终得到一个新的 UV，例如：

```text
UV(P)
≈
(0.4, 0.3)
```

Pixel Shader 就可以使用：

```text
(0.4, 0.3)
```

去 Texture 中采样。

---

# 十九、为什么 Texture 能连续铺满整个三角形

如果只有三个 Vertex 保存 UV，但 Triangle 内部完全不插值，那就只能知道：

```text
A 对应哪里
B 对应哪里
C 对应哪里
```

三角形内部的位置没有 UV。

Texture 就没法连续铺开。

正因为有插值：

```text
Vertex UV
↓
三角形内部连续插值
↓
每个 Fragment 都得到自己的 UV
```

所以一张二维图片才能连续地贴到整个模型表面。

---

# 二十、Normal 是怎么插值的

Normal 也是类似。

三个 Vertex：

```text
Normal A
Normal B
Normal C
```

三角形内部 Fragment：

```text
Normal P
```

可以通过三个顶点的 Normal 插值得到。

于是相邻三角形之间的光照可以表现得更加连续。

这也是为什么：

> **低面数模型也可能看起来比真实几何更光滑。**

---

# 二十一、Vertex Color 是怎么插值的

例如：

```text
A = Red
B = Green
C = Blue
```

那么三角形内部会自动得到各种中间颜色。

所以只需要在三个 Vertex 上保存颜色，整个 Triangle 内部就能产生连续渐变。

---

# 二十二、哪些属性可以插值

渲染中非常常见的插值属性包括：

- UV
- Normal
- Vertex Color
- Position
- Tangent
- 自定义 Vertex Shader 输出

核心规律是：

> **那些希望在三角形表面连续变化的数据，非常适合插值。**

---

# 二十三、不是所有数据都适合插值

例如：

```text
Primitive ID
Material ID
某些离散标记
```

这些数据本质上不是连续变化的。

例如：

```text
ID = 1
ID = 2
```

中间插值得到：

```text
1.5
```

通常没有实际意义。

所以：

> **是否插值取决于这个数据本身有没有“连续中间值”的意义。**

---

# 二十四、Perspective-Correct Interpolation

到这里还需要知道一个重要事实：

> 屏幕上的 Triangle 已经经过透视投影。

透视投影会产生：

```text
近大
远小
```

如果我们直接在屏幕二维坐标中简单线性插值某些属性，例如 UV，结果可能会产生透视错误。

所以真实 GPU 会使用：

# Perspective-Correct Interpolation

也就是：

> **透视校正插值。**

这一节不需要推导数学公式。

只需要先知道：

> 三角形内部看起来是在做插值，但对于 UV 等数据，GPU 会考虑透视关系进行校正，而不是简单地按二维屏幕距离直接插值。

后面如果深入 Shader 和底层管线，再研究具体数学实现。

---

# 二十五、为什么这一节必须知道“插值”

如果不知道插值，后面很多现象只能死记：

```text
为什么一个 Triangle 只有三个 Vertex，
里面却每个 Fragment 都有 UV？

为什么 Normal 能平滑变化？

为什么 Vertex Color 会形成渐变？

为什么 Vertex Shader 输出的数据，
Pixel Shader 可以在 Triangle 内部得到不同结果？
```

答案其实都是同一件事：

# Interpolation

所以插值真正解释的是：

> **少量顶点数据，为什么能够变成大量 Fragment 数据。**

---

# 二十六、把前几节完整串起来

现在可以得到一条非常重要的链：

```text
3D Model
↓
Triangle
↓
Vertex
↓
Vertex Attributes
Position / UV / Normal / Tangent / Color
↓
Projection
↓
Rasterization
↓
Fragment
↓
Interpolation
↓
Fragment 得到自己的 UV / Normal / Color ...
↓
进入后续 Shader
```

---

# 二十七、本节核心总结

## Position

> 决定顶点在空间中的位置，以及模型几何形状。

## UV

> 建立 3D 模型表面和二维 Texture 之间的坐标对应关系。

## Normal

> 描述表面朝向，是光照计算的重要基础。

## Tangent

> 描述沿表面的一个方向，常用于建立 Tangent Space 和处理 Normal Map。

## Vertex Color

> 顶点上的 RGBA 数据，既可以表示颜色，也可以作为材质 Mask 和 Shader 控制数据。

## Interpolation

> 根据已知顶点的数据，计算三角形内部 Fragment 对应的数据。

## Lerp

> 两个值之间最基础的线性插值。

## 三角形内部插值

> 根据 Fragment 在 Triangle 内的位置，对 A、B、C 三个顶点数据按权重组合。

## Perspective-Correct Interpolation

> 考虑透视投影后，对 UV 等属性进行正确插值的方法。
