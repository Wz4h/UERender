# UE 渲染系统 03：电脑到底怎么表示一个 3D 模型？

## 一、本节目标

前两节我们已经建立了两个最基础的认识：

第一，显示器最终看到的是一张二维图片。

第二，3D 游戏内部虽然保存的是一个三维世界，但玩家真正看到的，是摄像机视角对应的二维结果。

这一节继续往下追问：

> **游戏里的“球”“人物”“汽车”“建筑”，在计算机里到底是什么？**

我们人看到一个 Sphere，会直接理解成：

> 这是一个球。

但 GPU 并不理解“球”这个概念。

它真正能够处理的是：

- 数字
- 坐标
- 顶点
- 连接关系
- 表面

所以这一节的核心目标，就是理解：

> **一个 3D 模型到底是怎么被表示出来的。**

这一节主要学习：

1. 什么是 Vertex
2. 什么是 Edge
3. 什么是 Face
4. 什么是 Mesh
5. 为什么复杂曲面需要离散表示
6. 为什么实时渲染大量使用三角形
7. 为什么四边形和 N 边形最终通常会被三角化
8. 低模和高模到底区别在哪里
9. 为什么模型更像“一层表面壳”，而不是一个实心物体

---

# 二、GPU 并不认识“球”“人”“汽车”

我们先从一个非常直观的问题开始。

在 UE 场景里放一个 Sphere。

我们看到它以后，会自然认为：

> 这是一个球。

但 GPU 并不会理解：

```text
Sphere
```

这个语义。

同样：

```text
Character
Car
Tree
House
Weapon
```

这些名字，本质上都是给人看的。

GPU 真正需要的是：

> 这个物体的表面具体在哪里？

也就是说，GPU 并不关心：

> “它叫什么？”

而更关心：

> “它的几何数据是什么？”

所以计算机需要一种统一的方式，描述各种复杂 3D 物体的表面。

---

# 三、什么是 Vertex

最基础的几何元素之一，就是：

# Vertex —— 顶点

一个顶点，可以先理解成：

> 3D 空间中的一个位置。

例如：

```text
Vertex A

X = 0
Y = 0
Z = 0
```

另外一个：

```text
Vertex B

X = 100
Y = 0
Z = 0
```

也就是说，一个顶点最基础的信息就是：

```text
Position
=
(X, Y, Z)
```

它告诉我们：

> 这个点位于 3D 空间中的什么地方。

---

# 四、一个点还不能构成物体

如果只有一个顶点：

```text
•
```

那它只是一个位置。

两个顶点：

```text
•------•
```

可以形成一条连接关系。

但仍然没有形成一个真正的“表面”。

如果我们想描述：

- 一张纸
- 一个墙面
- 一个人脸
- 一个球面

最终都需要描述：

> 表面。

所以顶点之间还需要建立连接关系。

---

# 五、什么是 Edge

两个顶点之间的连接，可以理解成：

# Edge —— 边

例如：

```text
A -------- B
```

这里：

```text
A
B
```

是两个顶点。

它们之间的连接关系，就是：

```text
Edge
```

所以我们可以先理解：

```text
Vertex
=
点

Edge
=
点之间的连接
```

但是：

> 点和边本身仍然不能完整描述一个有面积的表面。

于是还需要：

# Face

---

# 六、什么是 Face

多个顶点和边围起来以后，可以形成：

# Face —— 面

例如：

```text
A------B
|      |
|      |
D------C
```

这就是一个表面区域。

对于一个 3D 模型来说，我们真正看到的：

- 人脸
- 衣服
- 墙
- 球
- 地面

本质上都来自：

> 大量表面组合在一起。

所以可以先形成：

```text
Vertex
↓
Edge
↓
Face
↓
复杂表面
```

---

# 七、什么是 Mesh

当大量：

- Vertex
- Edge
- Face

组合在一起时，就形成：

# Mesh —— 网格

可以先简单理解成：

> **用大量点、边、面共同描述出来的一个 3D 几何物体。**

例如：

```text
人物模型
```

本质上就是一个复杂 Mesh。

```text
汽车模型
```

也是 Mesh。

```text
Sphere
```

也是 Mesh。

所以：

> “模型”是一个比较直观的说法，而 Mesh 更接近计算机实际处理的几何结构。

---

# 八、为什么复杂曲面不能直接存成“光滑曲面”

现在考虑一个 Sphere。

我们肉眼看到的是：

> 一个连续、光滑的球面。

但一个真正数学意义上的光滑球面，理论上有：

> 无限多个位置。

例如数学上的球可以由一个方程描述：

```text
x² + y² + z² = r²
```

这是一个连续曲面。

但游戏不能真的保存：

> 无限多个点。

所以就需要把连续曲面：

```text
连续表面
```

变成：

```text
有限数量的几何数据
```

这就是一种：

> 离散化。

---

# 九、什么叫离散化

假设我们想描述一个圆。

真正的圆是连续的。

但计算机可以用很多小线段去近似：

```text
线段很少
↓
看起来像多边形

线段越来越多
↓
越来越接近圆
```

3D 曲面也是类似。

例如一个球：

```text
真正想表达
=
连续球面

计算机实际保存
=
大量小的平面
```

这些小平面越来越多以后：

> 人眼就会感觉它越来越接近光滑球面。

---

# 十、为什么最终大量使用三角形

现在问题来了：

> 如果我们要用很多“小平面”来表示复杂表面，为什么最终大量选择三角形？

这是实时图形学中非常重要的一个设计。

---

# 十一、原因一：三角形是最简单的面

一个面至少需要：

```text
3 个点
```

两个点只能形成一条线。

三个不共线的点就可以形成一个真正具有面积的表面。

所以：

> 三角形是最简单的二维面。

例如：

```text
    A
   / \
  /   \
 B-----C
```

这已经是一个完整表面。

---

# 十二、原因二：三个点一定能够确定一个平面

这是三角形非常重要的性质。

三个不共线的点：

```text
A
B
C
```

一定能够确定一个平面。

所以三角形本身永远是：

> 平的。

这使得它非常稳定。

---

# 十三、为什么四边形没有那么稳定

例如一个四边形：

```text
A------B
|      |
|      |
D------C
```

看起来没有问题。

但如果：

```text
C
```

稍微翘起来，

那么：

```text
A
B
C
D
```

四个点就可能不在同一个平面。

于是这个“四边形表面”到底应该怎么解释，就不再唯一。

但如果拆成两个三角形：

```text
A------B
|     /|
|   /  |
| /    |
D------C
```

就变成：

```text
Triangle 1
+
Triangle 2
```

每个三角形都一定是平面。

所以三角形的几何性质非常稳定。

---

# 十四、原因三：任意复杂表面都可以用三角形近似

这是三角形真正强大的地方。

无论我们想表达：

- 球
- 人脸
- 石头
- 汽车
- 地形
- 衣服
- 建筑

都可以用：

```text
大量小三角形
```

去近似。

所以最终可以统一成：

```text
所有复杂模型
↓
大量三角形
```

GPU 不需要分别知道：

```text
怎么画球
怎么画人物
怎么画汽车
怎么画石头
```

只需要非常擅长：

> 处理三角形。

---

# 十五、统一是非常重要的

如果每一种物体都有自己的几何表示方式：

```text
球
使用一种算法

人物
使用另一种算法

汽车
再使用另一种算法

树
又一种算法
```

那么整个渲染系统会变得极其复杂。

但如果最后全部统一成：

```text
Triangle
```

那么 GPU 可以使用同一套流程处理。

所以三角形的意义之一就是：

> **提供一种统一、简单、稳定的几何表示。**

---

# 十六、一个 Sphere 真的是球吗

严格来说：

> UE 里的普通 Sphere 并不是数学意义上的完美球体。

它更像：

```text
大量小三角形
↓
拼成一个近似球面
```

如果三角形数量比较少：

> 会明显看到棱角。

如果三角形越来越多：

> 看起来越来越圆。

所以：

```text
真正的连续曲面
↓
通过大量三角形近似
↓
得到游戏里的 Mesh
```

---

# 十七、低模和高模到底区别在哪里

这时候就可以理解：

# Low Poly

和：

# High Poly

最基础的区别之一。

## Low Poly

意味着：

> 使用较少的几何面去描述模型。

例如一个球：

```text
三角形少
↓
轮廓更有棱角
```

## High Poly

意味着：

> 使用更多的几何细节。

例如：

```text
三角形更多
↓
表面更加细腻
↓
轮廓更加接近光滑曲面
```

所以：

> 所谓“圆”，很多时候只是三角形数量足够多以后产生的视觉效果。

---

# 十八、为什么 Wireframe 能看到三角形

在 UE 中切换：

```text
Wireframe
```

以后，会看到模型表面出现大量线条。

这些线条展示的，就是：

> 网格几何结构。

例如正常模式下一个 Sphere：

```text
看起来是一个光滑球体
```

切到 Wireframe：

```text
会看到大量小三角形
```

这就说明：

> 我们看到的“球”，底层其实是一个三角形网格。

Wireframe 是理解 Mesh 最直观的方式之一。

---

# 十九、四边形是不是没用

不是。

在建模过程中，四边形：

# Quad

非常常见。

美术在建模时，经常更喜欢使用 Quad。

因为：

- 更容易编辑拓扑
- 更容易做环线
- 更容易做角色变形
- 更方便建模工作流

所以：

> 建模阶段大量使用四边形非常正常。

但到了实时渲染阶段：

> 最终通常还是会被转换成三角形。

---

# 二十、什么是 Triangulation

把四边形、多边形等转换成三角形的过程，可以叫：

# Triangulation —— 三角化

例如：

```text
A------B
|      |
|      |
D------C
```

可以拆成：

```text
A------B
|     /|
|   /  |
| /    |
D------C
```

于是：

```text
一个 Quad
↓
两个 Triangle
```

如果是一个五边形：

```text
5 边形
↓
可以拆成多个三角形
```

所以最终 GPU 可以统一处理。

---

# 二十一、是不是所有 3D 数据天生都是三角形

不是。

这一点非常重要。

有些 3D 数据本身可能是：

- NURBS 曲面
- Bézier 曲面
- CAD 曲面
- 数学曲面
- 体素
- SDF
- 程序生成几何

它们一开始并不一定是 Triangle Mesh。

但是如果最终要走传统实时光栅化管线：

```text
原始几何表示
↓
生成有限顶点
↓
组成三角形
↓
GPU 渲染
```

所以：

> 三角形不是所有 3D 世界唯一可能的表示方式。

但是：

> **它是现代实时光栅化渲染中最核心、最常见的几何表示方式。**

---

# 二十二、模型其实不是“实心”的

这是一个非常有意思、也非常重要的认知。

我们看到一个：

```text
Cube
```

会自然认为：

> 这是一个实心方块。

看到一个人物：

> 会觉得里面存在身体。

但对于渲染来说：

> 很多情况下，我们真正需要的只是物体表面。

例如一个 Cube：

```text
外表面
```

能把内部完全挡住。

那 GPU 根本没有必要保存：

```text
Cube 内部每一个位置
```

它只需要知道：

> 外壳在哪里。

所以一个普通 Mesh 更像：

> **由大量几何面组成的一层壳。**

---

# 二十三、为什么只需要表面

因为渲染最关心的是：

> 摄像机看过去，会看到什么表面。

如果一个物体内部完全看不到：

> 内部的数据对这一帧画面没有直接意义。

例如一个封闭的球：

```text
外面
=
能看到

内部
=
通常看不到
```

所以只需要描述：

```text
球面
```

而不是描述整个球内部每个位置。

这可以大幅减少需要存储和处理的数据。

---

# 二十四、为什么有时候钻进模型内部会很奇怪

如果模型只是一层表面壳，

当摄像机进入模型内部以后：

> 可能会出现非常奇怪的现象。

例如：

- 内部什么都没有
- 某些面从里面看不到
- 模型像“消失”一样

这会引出后面一个重要概念：

# Backface Culling —— 背面剔除

后面的课程再详细讲。

现在只需要建立：

> 普通 Mesh 并不等价于真实世界中的“实心物体”。

---

# 二十五、顶点是不是只有位置

也不是。

到目前为止，我们只把 Vertex 理解成：

```text
Position
=
(X,Y,Z)
```

这是为了方便入门。

真实游戏里的顶点还可能携带：

- Normal
- UV
- Tangent
- Vertex Color
- Bone Weight
- 其他自定义数据

这些数据以后都会参与渲染。

但是现在只需要先记住：

> 顶点是整个 Mesh 最基础的数据单元之一。

---

# 二十六、为什么三角形不仅适合描述表面

三角形还有一个非常重要的优势：

> 三角形内部的数据非常容易根据三个顶点进行插值。

例如：

```text
顶点 A
顶点 B
顶点 C
```

各自拥有不同的：

```text
UV
Normal
Color
```

那么三角形内部的位置，可以根据三个顶点自动计算出对应的数据。

这会在后面的课程中非常重要。

因为 GPU 后面需要根据三角形内部的位置：

> 计算贴图、光照和最终颜色。

所以三角形不仅：

> 容易表示表面。

还：

> 非常适合后续渲染计算。

---

# 二十七、本节最重要的逻辑

这一节最核心的逻辑不是：

> “模型由三角形组成。”

而是：

```text
计算机需要描述任意复杂 3D 表面
↓
连续曲面无法直接保存无限细节
↓
需要用有限数据进行近似
↓
使用大量简单几何面
↓
三角形简单、稳定、统一
↓
复杂模型最终可以表示成 Triangle Mesh
```

所以三角形不是凭空出现的。

它是在解决：

> **怎么让计算机统一表示复杂 3D 表面**

这个问题。

---

# 二十八、现在回到前两节

第一节我们知道：

```text
最终需要一张二维图片
```

第二节知道：

```text
3D 世界
↓
摄像机
↓
投影
↓
二维画面位置
```

这一节又知道：

```text
3D 模型
↓
Mesh
↓
大量三角形
```

所以现在可以得到：

```text
3D 世界中的模型
↓
由大量三角形表示
↓
摄像机观察
↓
三角形被投影到二维画面
```

到这里，我们离最终像素已经非常近了。

# 二十九、但现在还有一个新问题

假设一个三角形已经投影到了屏幕上：

```text
      A
     / \
    /   \
   B-----C
```

屏幕最终却不是连续平面。

而是：

```text
[ ][ ][ ][ ][ ]
[ ][ ][ ][ ][ ]
[ ][ ][ ][ ][ ]
[ ][ ][ ][ ][ ]
```

也就是：

> 离散的像素位置。

所以接下来必须解决：

> **这个三角形到底覆盖了屏幕上的哪些位置？**

这就会引出下一节：

# Rasterization —— 光栅化

# 三十、本节核心总结

这一节只需要真正理解下面这些内容。

## 1. GPU 不理解“物体语义”

```text
球
人
汽车
```

这些是人的理解。

GPU 需要：

```text
几何数据
```

## 2. Vertex

```text
Vertex
=
3D 空间中的基础点数据
```

## 3. Edge

```text
Edge
=
顶点之间的连接
```

## 4. Face

```text
Face
=
由顶点围成的表面
```

## 5. Mesh

```text
Mesh
=
由大量顶点、边、面组成的几何结构
```

## 6. 为什么需要离散化

连续曲面理论上拥有无限细节。

计算机只能保存有限数据。

所以需要：

```text
连续曲面
↓
有限几何
↓
近似表示
```

## 7. 为什么使用三角形

因为三角形：

- 是最简单的面
- 三个点一定确定一个平面
- 几何稳定
- 可以近似任意复杂表面
- 非常适合 GPU 统一处理
- 非常适合后续插值和光栅化

## 8. 模型不一定是实心

普通 Mesh 更接近：

```text
一层几何表面壳
```

而不是：

```text
内部全部存在几何数据的实体
```
