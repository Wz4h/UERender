# UE 渲染系统 05：光栅化、采样与片元

## 一、本节目标

前面我们已经知道：

- 3D 模型通常由大量三角形组成
- 三角形经过摄像机和投影后，会变成屏幕上的二维三角形
- 屏幕最终由一个个离散的 Pixel 组成

但这里还有一个关键问题：

> **连续的二维三角形，怎么和离散的 Pixel 联系起来？**

这一节就围绕四个重点展开：

1. 联系三角形和 Pixel 的是 Sample
2. 什么是 Fragment
3. Fragment 有什么作用
4. Fragment 的数量应该怎么理解

---

# 二、三角形和 Pixel 之间为什么需要 Sample

二维三角形是连续几何。

而 Pixel 是离散输出位置。

也就是说：

```text
Triangle
=
连续区域

Pixel
=
离散位置
```

两者不能直接一一对应。

GPU 需要一个明确的方法判断：

> **这个三角形到底影响了哪些 Pixel？**

这时就引入：

# Sample —— 采样位置

---

# 三、什么是 Sample

Sample 可以先理解成：

> **Pixel 内部用于判断几何覆盖关系的采样位置。**

最简单的情况下：

```text
1 Pixel
≈
1 Sample
```

例如：

```text
Pixel

┌─────────┐
│    •    │
└─────────┘
     ↑
   Sample
```

GPU 不直接模糊地判断：

> 三角形有没有碰到这个 Pixel？

而是判断：

> **这个三角形有没有覆盖这个 Sample？**

所以可以把 Sample 理解成：

> **联系连续三角形和离散 Pixel 的检测位置。**

---

# 四、为什么不能直接判断“像素属于哪个三角形”

因为同一个 Pixel 位置，可能同时被多个三角形覆盖。

例如：

```text
Triangle A
↓
覆盖 Sample S

Triangle B
↓
也覆盖 Sample S
```

所以并不存在：

> 这个 Pixel 只属于某一个三角形

这种唯一归属关系。

更准确的问题应该是：

> **这个三角形覆盖了哪些 Sample？**

所以光栅化的处理方向，更接近：

```text
Triangle
↓
检查它覆盖哪些 Sample
```

而不是：

```text
Pixel
↓
判断它属于哪个 Triangle
```

---

# 五、光栅化到底在做什么

可以用一句话概括：

> **光栅化通过检查三角形对 Sample 的覆盖关系，把连续的二维三角形转换成离散的屏幕覆盖结果。**

整个过程可以先理解成：

```text
二维三角形
↓
Rasterization
↓
检查哪些 Sample 被覆盖
↓
为这些被覆盖位置产生后续渲染需要的数据
```

这就引出：

# Fragment —— 片元

---

# 六、什么是 Fragment

Fragment 最容易被误解成：

- 一个小像素
- 一个点
- 一个有面积的小方块

这些都不准确。

更合适的理解是：

> **Fragment 是某个三角形在某个被覆盖屏幕位置上产生的一份候选渲染数据。**

也就是说：

```text
Sample
=
位置

Fragment
=
某个三角形在这个位置产生的数据
```

你可以把 Fragment 理解成一张候选记录。

例如：

```text
Fragment
{
    ScreenPosition
    Depth
    UV
    Normal
    VertexColor
    ...
}
```

所以 Fragment 本质上是：

> **数据**

而不是一个真正有面积的几何块。

---

# 七、Sample 和 Fragment 到底有什么区别

这是这一节最重要的区别之一。

## Sample

Sample 回答的是：

> **在哪里判断？**

它是一个采样位置。

---

## Fragment

Fragment 回答的是：

> **这个三角形在这个位置带来了什么数据？**

它是一份候选渲染数据。

所以可以记成：

```text
Sample
=
位置

Fragment
=
数据
```

或者更直白一点：

> **Sample 是“在哪”，Fragment 是“这里有什么”。**

---

# 八、Fragment 是怎么产生的

假设一个三角形投影到屏幕后覆盖了某个 Sample：

```text
Triangle
↓
覆盖 Sample
```

光栅化阶段就会针对这个被覆盖的位置产生 Fragment 候选：

```text
Triangle
↓
Rasterization
↓
Fragment
```

所以在最简单的理解里：

```text
一个三角形
↓
覆盖多少个需要处理的 Sample
↓
就会对应产生多少份 Fragment 候选
```

---

# 九、一个具体例子

假设屏幕非常小。

某个 Triangle A 覆盖了 5 个 Sample：

```text
Triangle A
↓
覆盖 5 个 Sample
↓
产生约 5 份 Fragment 候选
```

Triangle B 覆盖了 3 个 Sample：

```text
Triangle B
↓
覆盖 3 个 Sample
↓
产生约 3 份 Fragment 候选
```

那么在最简单的单采样情况下，可以近似理解为：

```text
总 Fragment 数量
≈
5 + 3
=
8
```

如果：

```text
Triangle A
和
Triangle B
```

都覆盖了同一个 Sample，

也仍然会产生两份不同的 Fragment 候选。

因为：

```text
Fragment A
来自 Triangle A

Fragment B
来自 Triangle B
```

它们不是同一份数据。

---

# 十、Fragment 数量应该怎么理解

这一节可以先建立一个非常实用的近似：

> **在最简单的单采样、传统三角形光栅化情况下，Fragment 数量可以近似理解为所有三角形覆盖的 Sample 数量之和。**

例如：

```text
Triangle A
覆盖 100 个 Sample

Triangle B
覆盖 80 个 Sample

Triangle C
覆盖 50 个 Sample
```

那么：

```text
Fragment 候选数量
≈
100 + 80 + 50
=
230
```

注意：

> 这是一个帮助理解的近似模型。

真实 GPU 中还会受到：

- MSAA
- Early-Z
- Sample Shading
- 辅助执行
- 其他优化机制

等影响。

但对于现在理解光栅化，非常够用。

---

# 十一、这说明三角形数量不是唯一成本

这个结论很重要。

假设：

```text
模型 A
有很多很小的三角形

模型 B
只有一个巨大三角形
```

如果模型 B 的这个三角形几乎覆盖整个屏幕，

那么即使它只有一个 Triangle，也可能覆盖大量 Sample。

所以：

> **屏幕覆盖面积也会直接影响 Fragment 数量。**

这也是为什么实时渲染里不能只盯着：

```text
Triangle Count
```

还要关注：

```text
Screen Coverage
```

---

# 十二、Fragment 的作用是什么

光栅化本身主要解决的是：

> **这个三角形覆盖了哪里？**

但覆盖之后，GPU 还要继续计算：

- 这里是什么颜色
- 这里的 UV 是多少
- 这里的 Normal 是多少
- 这里距离摄像机有多远
- 这里有没有被其他物体挡住
- 这里需不需要透明混合

这些后续处理都需要数据。

Fragment 就是：

> **几何覆盖阶段和后续着色阶段之间的数据载体。**

所以可以把 Fragment 理解成：

> 光栅化把“这个三角形覆盖了这里”转换成一份后续可以继续处理的数据。

---

# 十三、光栅化产生 Fragment 后，后面还会继续处理

Fragment 不是最终结果。

它只是：

> 候选渲染数据。

后续还会继续处理 Fragment 里的数据。

例如：

```text
Fragment
↓
Pixel Shader
↓
计算颜色
↓
Depth Test
↓
判断是否被挡住
↓
Blending
↓
必要时和已有颜色混合
↓
写入最终 Pixel
```

所以：

```text
Fragment
≠
Pixel
```

Fragment 是：

> 过程中的候选数据

Pixel 是：

> 最终图像中的输出位置

---

# 十四、最终 Pixel 的颜色和 Fragment 有什么关系

一个 Pixel 最终显示什么颜色，

是由影响这个 Pixel 的 Fragment 经过后续处理后决定的。

例如同一个 Pixel 位置：

```text
Fragment A
Color = Red
Depth = 0.2

Fragment B
Color = Blue
Depth = 0.8
```

如果 A 更靠近摄像机，

深度测试后可能得到：

```text
Fragment A 保留
Fragment B 被挡住
```

那么最终：

```text
Pixel
=
Red
```

如果存在半透明，

还可能需要多个 Fragment 进行颜色混合。

所以更准确地说：

> **最终 Pixel 的信息由作用于它的 Fragment 经过着色、深度测试、混合等过程共同决定。**

不是简单地：

> Fragment 像积木一样拼成 Pixel。

而是：

> Fragment 提供候选数据，后续规则决定 Pixel 最终保存什么。

---

# 十五、整节课最重要的一条链

可以把整个过程记成：

```text
Triangle
↓
投影到屏幕
↓
二维 Triangle
↓
检查覆盖哪些 Sample
↓
Rasterization
↓
产生 Fragment
↓
继续处理 Fragment 数据
↓
Shader / Depth / Blend
↓
最终 Pixel
```

这条链里：

```text
Triangle
=
连续几何

Sample
=
联系几何和 Pixel 的检测位置

Fragment
=
某个三角形在被覆盖位置产生的候选数据

Pixel
=
最终图像输出位置
```

---

# 十六、本节最核心的四个结论

## 1. 联系三角形和 Pixel 的是 Sample

> Sample 是连续三角形和离散 Pixel 之间的检测位置。

---

## 2. Fragment 是数据，不是小方块

> Fragment 是某个三角形在一个被覆盖屏幕位置上产生的一份候选渲染数据。

---

## 3. Fragment 数量和三角形覆盖量密切相关

在最简单情况下：

```text
Fragment 数量
≈
所有三角形覆盖 Sample 数量之和
```

---

## 4. Fragment 还会继续被处理

Fragment 不是最终 Pixel。

它还要经过：

- Shader
- Depth Test
- Blending
- 其他后续处理

最后才决定最终 Pixel 的信息。
